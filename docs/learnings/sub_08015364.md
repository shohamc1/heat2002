## Missing source constraint: a second call argument

The successful state2 lookup is:

```c
dst = &gUnk_020020CC;
p = gUnk_083FDE2D;
p += *(volatile u8 *)&gUnk_0202ED70;
*dst = *p;
sub_0800F8D0(gUnk_0202ED70, dst);
gUnk_0202EEB0 = one;
```

`one` is an `s8` local initialized to 1 before the setup calls. `dst` and
`p` are `u8 *` locals. The callee takes `(u8, u8 *)`, ignoring the pointer.
Its retail entry overwrites incoming r1 at `0x0800F8EE` before reading it;
adding the unused parameter to its definition still matches all 1956 bytes.
This is the only caller found in source/assembly.

The second argument gives `dst` a hard-register r1 suggestion during local
allocation. It needs no extra machine instruction: the preceding table store
already has that address in r1. The updated `p` accumulator takes r0, the
volatile index gets r2, and rematerializing `one` also gets r2 after the call.
The old arguments assumed all allocation decisions arose from priority alone,
missing the earlier hard-register-suggestion pass in `local-alloc.c`.

Both declarations now agree, avoiding incompatible cross-translation-unit
function types. This is an ABI-compatible reconstruction, not proof of the
original author's signature or intended use of the unused argument.
